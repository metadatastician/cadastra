== Limits — read these before trusting a row

Stale by construction:: The report is an observation at a moment. It is stale as
soon as any scanned repo changes. Re-run rather than trust the date.

Visibility-bounded:: It covers what the scanning credential could read. Absence
from the report is *not* evidence a repo does not exist.

Local language detection samples:: `detect_languages_local()` inspects at most the
first 500 files per repo (`find ... | head -500`). A language that appears only in
file 501+ of a large repo will be missed, so a `local:` row's language list is a
sample, not an inventory. The `github:` rows do not have this limit — they use
GitHub's own computed language set.

Anti-pattern detection is textual:: The detectors are `grep`/`find` heuristics, not
semantic analysis. `UNVERIFIED_RUST` means "a Cargo.toml exists and no proof-tool
marker was found by grep" — not that the crate is unverified in fact. Treat every
anti-pattern as a lead to confirm, not a finding.

`DIRECT_FFI_NO_HEXADECA` is the noisiest signal:: 457 of 762 rows carry it. Its
pattern includes bare `extern "C"`, which matches ordinary Rust/Zig FFI and much
vendored C. Expect a high false-positive rate; do not read 457 as 457 real defects.

Classification is coarse:: `classify_repo()` keys off language presence plus
anti-patterns. `KILL` means "a banned language and no target-stack language was
detected" — a judgement about *observed code*, never a recommendation about the
project. All 8 KILL rows are the owner's to adjudicate.

== Fixes applied to the scanner before this run

The toolkit as received could not produce a correct report. Three defects were
fixed at source; `scripts/estate-scan.sh` here is the fixed copy.

. *Wrong language path (silent wrong answers).* The jq read `.languages[].name`,
but `gh` nests it at `.languages[].node.name`, so every GitHub repo got an EMPTY
language list. With no languages, `classify_repo()` saw neither banned nor target
languages and fell through to `DONE`/`CLEAN` — *no GitHub repo could ever be
classified `KILL` or `MIGRATE`*. This was the dangerous one: it fails silently and
reports a clean estate.

. *No retry on an expensive query (fatal aborts).* Requesting `languages` across
424 repos is an expensive GraphQL query that GitHub intermittently answers with
HTTP 502. Under `set -euo pipefail` a single 502 aborted the whole run — including
the local scan, which never got to start. Now retried with backoff; a persistently
failing org is reported as INCOMPLETE and returns non-zero rather than passing
silently.

. *Broken summary counters.* `count=$(grep -c ... || echo "0")` concatenated to
`"0\n0"`, because `grep -c` prints `0` AND exits 1 on no-match — making every
zero-count summary line a `[[: syntax error`.

The unmodified original is preserved for comparison at
`developer/estate-migration-toolkit/scripts/estate-scan.sh.orig` (outside this repo).

== Reproducing

[source,bash]
----
tools/estate-migration-toolkit/scripts/estate-scan.sh \
  --github hyperpolymath metadatastician \
  --local ~/developer/hyper-repos ~/developer/meta-repos
----

Requires `gh` (authenticated), `jq`, and `git`. Writes `estate-triage-report.csv`
to the current directory. The scan is read-only: it clones to `mktemp -d` temp dirs
and removes them; it never writes to a scanned repo.
